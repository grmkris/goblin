## Emulator launcher follow-up

The native launch attempt found a dev-server port mismatch: the script started One on 18980, but `one run:android` read no port from Vite config and tried 8081. The Vite config now specifies 18980 with `strictPort: true`, matching the existing dev script. The README includes the required running dev server and connected emulator/device.

With One running on the corrected port, the Android launcher passed its dev-server check and exited 1 with:

```text
No Android device or emulator is connected. Start an emulator or plug in a device, then re-run this command.
```

An ADB query outside the sandbox confirmed no connected targets. The host has no installed emulator or AVD, no `/dev/kvm`, and no CPU virtualization extensions exposed to this VM. The existing SDK is also missing the generated project's required SDK/NDK. iOS requires a Mac. No emulator was booted and no native app was installed.

Initial network and ADB-socket failures were sandbox limitations: direct access to Google's SDK catalog and starting ADB succeeded outside it. They are not host-wide network failures. The older SDK manager emitted an XML-version warning and its catalog query was stopped after it stalled. No SDK packages were installed. Software emulation remains an untested, slower possibility; it would not establish device performance.

The temporary One dev server was stopped after the probe. This follow-up changes only the isolated spike's launcher configuration and documentation.
