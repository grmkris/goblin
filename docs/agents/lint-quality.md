# Quality gates

goblin has zero accepted lint, Effect or Knip findings and no baseline. The rule set was adapted from My Apps;
the vendored rules keep their upstream provenance and license under `tools/oxlint/anti-slop/`.

`bun run check` runs format, agent/docs checks, graph, typecheck, the spikes' typecheck and tests (`check:spikes`; install `spikes/coding` and `spikes/coding-cf` with `bun install --frozen-lockfile` first, as CI does; the native verifier regression needs a prepared snapshot and stays out), the zero-finding lint/Effect/Knip gate, duplication, unit/runtime tests and the production build. Run expensive checks through `heavy` on this box. Never pipe `heavy`; exit 75 means capacity contention. Gate collectors do not nest `heavy` calls.

Oxlint enables correctness/suspicious categories, TypeScript type-aware rules, Oxc, Unicorn, import, a trimmed set of anti-slop rules (SAFETY-commented assertions, no chained or widen-then-assert assertions, no module mocking, no Reflect get/apply, Effect tag rules), runtime/import boundaries, repository configuration/resource-name rules, cognitive complexity, and shadcn rules. Oxfmt owns formatting. Use a consistent nearest `tsconfig.json` for TypeScript and type-aware diagnostics; do not use `oxlint --type-check` as the type gate.

Budgets are 500 code lines/file, 80/function, depth 4, five parameters, and cognitive complexity 15. Tests retain 1000 lines/file with function-length relaxed because the describe block is the file outline. Components own their styling only under `packages/ui/src/components`; shadcn token/color/class checks remain active.

`goblin/no-silent-catch` keeps failures visible. A handler that catches one must pass it on or report it: a `catch` clause, a `.catch(cb)` callback, the handler of `Effect.catch`, `catchCause`, `catchIf`, `orElse` or `orElseSucceed`, and every `Effect.ignore` or `ignoreCause`. It passes when something inside it throws, returns or yields a failure (`Effect.fail`, `failCause`, `die`, `Effect.interrupt`, `yield* new X()`, `Promise.reject`, `reject(...)`) or calls a reporter (`reportFailure`, `reportAndRecover`, any `report*`, `logEvent`, `writeLine`, `failureResponse`, or in the web `describeError`, `messageOf` and `authMessageOf`, which turn the failure into what the owner sees); a handler passed by name passes when the name is one of those. Typed handling (`catchTag`, `catchTags`) is not a catch-all and is not checked. When dropping the failure is right, say why on the line above the handler or as its first line: `// expected: <reason of at least ten characters>`.

The strict rules are on for every file: `no-console` (off only in the runtime logger, `apps/cli`, `tools`, the operator, build and spike scripts (`scripts`, `bench/scripts`, `packages/*/scripts`, `spikes/*/scripts`) and tests), `no-empty`, `prefer-promise-reject-errors`, `goblin/no-silent-catch`, `typescript/use-unknown-in-catch-callback-variable`, `typescript/no-floating-promises` without the `void` escape and the five `typescript/no-unsafe-*` rules (off, with `typescript/no-explicit-any`, in tests, fixtures, scripts, deploy and config files, which handle untyped JSON); every React file (`apps/web`, `packages/ui`, `packages/kit`, `packages/app/src/ui`) also runs `react/rules-of-hooks` and `react/exhaustive-deps`.

The web data layer's rules (`tools/oxlint/data-invariants.ts`, ported from My Apps with its tests) apply to `apps/web/src/`. `goblin/no-transport-outside-client`: a server call goes through the typed client inside a `queryFn` or `mutationFn`. `goblin/no-network-in-effect`: a React effect, nested callbacks included, starts no transport call and no `mutate`/`mutateAsync`; an SSE event may invalidate the cache. `goblin/no-loader-data` (`all` mode): views read API data from the Query cache, never `useLoaderData`. The transports are `fetch`, `XMLHttpRequest`, `EventSource`, `HttpClient.*`, `HttpApiClient.make`, `*.callTool` and `*.run` on a `makeApiQuery` result or an import from `lib/api*`. The transport modules are exempt: the client and its bridge (`lib/api*.ts`, `lib/query/**`), feature factories (`**/queries.ts`), the owner's file bytes, which the JSON API does not carry (`lib/files.ts`), and the two SSE stores (`lib/conversation-stream.ts`, `lib/workspace-feed.ts`). The same paths run the TanStack plugins' rules, as My Apps does: Query's `exhaustive-deps`, `no-rest-destructuring`, `stable-query-client`, `no-unstable-deps`, `prefer-query-options` and `mutation-property-order`, and Router's `create-route-property-order` and `route-param-names`.

Fix code before disabling a rule. Every disable names the exact rule and ends in `-- <concrete reason>` of at least ten characters. Effect diagnostic directives follow the same reason convention: one that turns a diagnostic off or lowers it to `warning`, `message` or `suggestion` needs a reason; one that raises it to `error` does not. Unused disables fail. Prefer Schema decoding, type guards, and fixing types at their source. An unavoidable assertion needs a preceding `// SAFETY:` statement of the invariant TypeScript cannot see. `as const` is exempt.

`tools/graph.ts` declares runtime zones and allowed workspace imports; manifest edges must match. Cloudflare APIs belong to cloud/runtime tests; Bun belongs to tooling; Node/Bun/Cloudflare imports are prohibited in browser and contract code. Runtime settings use Effect Config. Resource names derive from the deployment stage; Alchemy is the sole deployment authority.

Knip checks every issue class; configuration hints fail too (`treatConfigHintsAsErrors` in `knip.jsonc`): knip exits 1 for them, and `lint:gate` fails on a knip run that exits 1 with no issue (its JSON report leaves hints out). jscpd fails above 1.5% duplicate lines, with the reviewed generated/vendor/test exclusions. Effect diagnostics cover every typechecked project; an incomplete tool or unchecked project is a failure. `extendsNativeError` and `catchUnfailableEffect` are errors. Errors, warnings and `@effect-diagnostics` directives that change nothing (`effect(unusedDirective)`, effect-tsgo's 377000, counted only inside real comments) gate; messages and suggestions are editor advice. `unstableApiUsage` is off: the typed API is built on Effect's HTTP modules, and the exact version pin is their stability boundary. Do not silently record zero findings after parse, resolution, or runtime errors.
