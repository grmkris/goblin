# Quality gates

goblin has zero accepted lint, Effect or Knip findings and no baseline. The rule set was adapted from My Apps;
the vendored rules keep their upstream provenance and license under `tools/oxlint/anti-slop/`.

`bun run check` runs format, agent/docs checks, graph, typecheck (the TypeScript and Effect diagnostics), the zero-finding lint/Knip gate, duplication, unit/runtime tests and the production build. Run expensive checks through `heavy` on this box. Never pipe `heavy`; exit 75 means capacity contention. Gate collectors do not nest `heavy` calls.

Oxlint enables correctness/suspicious categories, TypeScript type-aware rules, Oxc, Unicorn, import, a trimmed set of anti-slop rules (SAFETY-commented assertions, no chained or widen-then-assert assertions, no module mocking, no Reflect get/apply, Effect tag rules), runtime/import boundaries, repository configuration/resource-name rules, cognitive complexity, and shadcn rules. Oxfmt owns formatting. Use a consistent nearest `tsconfig.json` for TypeScript and type-aware diagnostics; do not use `oxlint --type-check` as the type gate.

Budgets are 500 code lines/file, 80/function, depth 4, five parameters, and cognitive complexity 15, scored as the Sonar spec does (an `else`, each `switch` case and a nested callback's nesting count). Tests retain 1000 lines/file with function-length relaxed because the describe block is the file outline. Components own their styling only under `packages/ui/src/components`; shadcn token/color/class checks remain active. The base-ui triggers there (`CollapsibleTrigger`, `DrawerTrigger`, `DropdownMenuTrigger`, `PopoverTrigger`) set no classes: the control each renders through `render` is the app's own, styled by its class, and `shadcn/no-restyle` reads that element. Its contracts in `oxlint.config.ts` name exactly those classes per trigger; a new one is added there on purpose, and every other class on a trigger stays checked.

`goblin/no-silent-catch` keeps failures visible. A handler that catches one must pass it on or report it: a `catch` clause, a `.catch(cb)` callback, the handler of `Effect.catch`, `catchCause`, `catchIf`, `orElse` or `orElseSucceed`, and every `Effect.ignore` or `ignoreCause`. It passes when something inside it throws, returns or yields a failure (`Effect.fail`, `failCause`, `die`, `Effect.interrupt`, `yield* new X()`, `Promise.reject`, `reject(...)`) or calls a reporter (`reportFailure`, `reportAndRecover`, any `report*`, `logEvent`, `writeLine`, or in the web `describeError` and `messageOf`, which turn the failure into what the owner sees); a handler passed by name passes when the name is one of those. Typed handling (`catchTag`, `catchTags`) is not a catch-all and is not checked. When dropping the failure is right, say why on the line above the handler or as its first line: `// expected: <reason of at least ten characters>`.

The strict rules are on for every file: `no-console` (off only in the runtime logger, `apps/cli`, `tools`, the operator and build scripts (`scripts`, `packages/*/scripts`) and tests), `no-empty`, `prefer-promise-reject-errors`, `goblin/no-silent-catch`, `typescript/use-unknown-in-catch-callback-variable`, `typescript/no-floating-promises` without the `void` escape, `typescript/no-explicit-any` and the five `typescript/no-unsafe-*` rules (the unsafe rules are off in tests, scripts and config files, which handle untyped JSON); every React file (`apps/web`, `packages/ui`, `packages/kit`, `packages/app/src/ui`) also runs `react/rules-of-hooks` and `react/exhaustive-deps`. Their source (not test fixtures, which count renders and
poke at refs on purpose) also runs the React Compiler's checks of the Rules of React (`RULES_OF_REACT` in
`oxlint.config.ts`: `refs`, `purity`, `immutability`, `preserve-manual-memoization`,
`set-state-in-render`, `set-state-in-effect`, `static-components`, `use-memo`, `incompatible-library`,
`unsupported-syntax`, `globals`, `error-boundaries`): no ref read or written while rendering (write a "latest" ref in a
layout effect, or read it through `useEffectEvent`), no `Date.now()` while rendering (`useMinute`, `useNow`), and no
state set in an effect to catch up with something else (derive it while rendering, or read an external store with
`useSyncExternalStore`).

The web data layer's rules (`tools/oxlint/data-invariants.ts`, ported from My Apps with its tests) apply to `apps/web/src/`. `goblin/no-transport-outside-client`: a server call goes through the typed client inside a `queryFn` or `mutationFn`. `goblin/no-network-in-effect`: a React effect, nested callbacks included, starts no transport call and no `mutate`/`mutateAsync`; an SSE event may invalidate the cache. `goblin/no-loader-data` (`all` mode): views read API data from the Query cache, never `useLoaderData`. The transports are `fetch`, `XMLHttpRequest`, `EventSource`, `HttpClient.*`, `HttpApiClient.make`, `*.callTool` and `*.run` on a `makeApiQuery` result or an import from `lib/api*`. The transport modules are exempt: the client and its bridge (`lib/api*.ts`, `lib/query/**`), feature factories (`**/queries.ts`), the owner's file bytes, which the JSON API does not carry (`lib/files.ts`), and the live reads (`lib/event-streams.ts`: a chat's AG-UI stream over `fetch` and `EventSource`, and the workspace feed's `BrowserFeedSource`; `lib/agui/` and `lib/workspace/` themselves call no transport). The same paths run the TanStack plugins' rules, as My Apps does: Query's `exhaustive-deps`, `no-rest-destructuring`, `stable-query-client`, `no-unstable-deps`, `prefer-query-options` and `mutation-property-order`, and Router's `create-route-property-order` and `route-param-names`.

Fix code before disabling a rule. Every disable names the exact rule and ends in `-- <concrete reason>` of at least ten characters. Effect diagnostic directives follow the same reason convention: one that turns a diagnostic off or lowers it to `warning`, `message` or `suggestion` needs a reason; one that raises it to `error` does not. Unused disables fail. Prefer Schema decoding, type guards, and fixing types at their source. An unavoidable assertion needs a preceding `// SAFETY:` statement of the invariant TypeScript cannot see. `as const` is exempt.

`tools/graph.ts` declares runtime zones, allowed workspace imports, the entries a workspace still may not import (`forbids`: the web never imports `@goblin/contracts/internal`), and the modules a workspace closes to all but the files it lists (`closed`: the runtime's bridge and `promiseWith`, `boundaries/no-closed-import`); manifest edges must match, and every closed module and listed importer must exist. Cloudflare APIs belong to cloud/runtime tests; Bun belongs to tooling; Node/Bun/Cloudflare imports are prohibited in browser and contract code. Runtime settings use Effect Config. Resource names derive from the deployment stage; Alchemy is the sole deployment authority.

Knip checks every issue class; configuration hints fail too (`treatConfigHintsAsErrors` in `knip.jsonc`): knip exits 1 for them, and `lint:gate` fails on a knip run that exits 1 with no issue (its JSON report leaves hints out). `lint:gate` runs knip twice: as configured, and in production mode (`bun run knip --production`), which reads only the entries and project files `knip.jsonc` marks with `!` and so reports code, files and dependencies that only tests use (`knip(production:<issue type>)`). Tests, test helpers, browser fixtures and build scripts are not production files. Tests build what they need from the production layers and functions, never a test-only class in `src`; an export production does not use but keeps on purpose says why under the JSDoc tag `@internal`, which production mode skips. jscpd fails above 1.5% duplicate lines, with the reviewed generated/vendor/test exclusions. TypeScript and Effect diagnostics run in one pass per project (ADR 0120): `bun run typecheck` runs effect-tsrs, a Rust port of the TypeScript 7 compiler with all of Effect's language-service diagnostics, once on every tsconfig a workspace's `typecheck` script names (`tools/typecheck.ts`, `tools/pass.ts`), and fails on a TypeScript error or an Effect diagnostic that gates. `bun run check` then runs `lint:gate --skip effect`, since the same pass has just run; `lint:gate` on its own still collects the Effect findings. Nothing in the gates runs tsc or effect-tsgo any more; the `EFFECT_CHECKER=tsgo` fallback went once parity held (ADR 0121). Editors keep `@effect/tsgo` and type-aware lint keeps oxlint-tsgolint. Every typechecked project must set or inherit the `@effect/language-service` plugin block (read from the tsconfig and what it extends, before the run); an incomplete tool or unchecked project is a failure. `extendsNativeError` and `catchUnfailableEffect` are errors. Errors, warnings and `@effect-diagnostics` directives that change nothing (`effect(unusedDirective)`, code 377000, counted only inside real comments) gate; messages and suggestions are editor advice. `unstableApiUsage` is off: the typed API is built on Effect's HTTP modules, and the exact version pin is their stability boundary. Do not silently record zero findings after parse, resolution, or runtime errors.

## User-facing punctuation

The owner decision of 25 October 2026 bans U+2014 em dashes in shipped UI, agent tool descriptions and error copy.
`goblin/no-em-dash-copy` checks literals, template fragments (including Unicode escapes) and JSX text in application
and package source. Use a comma, colon, parentheses or a new sentence. The sole placeholder exception is a
`const EMPTY_CELL` declaration containing only that character in `packages/ui/src/lib/empty-cell.ts`, if needed.
Comments and arbitrary user or remote text in tests retain their own punctuation.
